Nodal Control — State Diagrams

Updated 2026-04-17.

1. Panel Key (client-side visual state)

The state a key can be in while the crew is editing Panel Studio.

stateDiagram-v2
    direction LR

    [*] --> empty
    [*] --> assigned

    empty --> changed : pick an item
    assigned --> changed : pick a different item
    assigned --> empty : pick Unassigned

    changed --> submitted : Submit changes
    changed --> assigned : Discard

    submitted --> assigned : admin approved
    submitted --> changed : admin denied (revert)

    note right of empty : no pickListItem - gray key
    note right of assigned : saved in DB - labeled key
    note right of changed : local edit + KeyDraft(draft) - yellow
    note right of submitted : KeyDraft(submitted) - green

2. ChangeRequest lifecycle (server-side)

stateDiagram-v2
    direction TB

    [*] --> draft : created while editing

    draft --> submitted : user clicks Submit
    draft --> discarded : user cancels

    submitted --> mgr_endorsed : manager endorses
    submitted --> applied : admin approves any item
    submitted --> rejected : admin denies all items

    mgr_endorsed --> applied : admin approves any item
    mgr_endorsed --> rejected : admin denies all items

    applied --> [*]
    rejected --> [*]
    discarded --> [*]

    note right of submitted : appears in admin Tasks - badge increments
    note right of applied : resolvedAt set - PanelKey updated for approved items
    note right of rejected : resolvedAt set - no PanelKey changes

3. Equipment deploy status

Transitions are not enforced server-side — admin or crew can change to any value directly. This is the expected operational path.

stateDiagram-v2
    direction TB

    [*] --> na : equipment created

    na --> deployed : crew installs
    na --> not_needed : cut before deploy

    deployed --> done : show wraps
    deployed --> returned : pulled early
    deployed --> damaged : gear fails

    damaged --> returned : after teardown
    done --> returned : checked back in

    returned --> [*]
    not_needed --> [*]

    note right of na : gray badge
    note right of deployed : yellow badge
    note right of done : green badge
    note right of returned : blue badge
    note right of not_needed : red badge
    note right of damaged : purple badge

4. User first-login status

Drives the Team tab Active/Pending indicator. Derived from User.pin being null or not.

stateDiagram-v2
    direction LR

    [*] --> Pending : admin adds user (User.pin null)

    Pending --> Active : user sets personal PIN after first login

    Active --> [*]

    note right of Pending : Pending - amber text
    note right of Active : Active - green text

5. Account lockout

stateDiagram-v2
    direction LR

    [*] --> active

    active --> failing : wrong PIN
    failing --> failing : still wrong
    failing --> active : correct PIN resets counter

    failing --> locked : 10 failed attempts
    locked --> active : 15 min pass (lockedUntil expires)
    locked --> active : admin clicks Unlock in Tasks

    note right of failing : failedAttempts++ - lastFailedAt set
    note right of locked : lockedUntil = now + 15min - appears in Tasks
