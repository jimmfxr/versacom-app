Nodal Control — Sequence Diagrams

Updated 2026-04-17. Key flows showing who talks to who and in what order.

1. Join a project via QR code

sequenceDiagram
    actor Admin
    actor Crew
    participant ProjectUI as Project Detail UI
    participant JoinUI as login/join page
    participant Server as Server Action
    participant DB

    Admin->>ProjectUI: opens Team tab
    Admin->>ProjectUI: clicks Show QR (crew) or Add Member + QR (admin)
    ProjectUI->>ProjectUI: renders QR encoding URL with pin=1234

    Crew->>Crew: scans QR
    Crew->>JoinUI: loads login/join?pin=1234
    JoinUI->>JoinUI: pre-fills PIN digits
    Crew->>JoinUI: types first + last name, taps Join

    JoinUI->>Server: joinProject(firstName, lastName, pin)
    Server->>DB: find Project by pin

    alt existing user
        Server->>DB: ensure ProjectMember
        Server-->>JoinUI: needsPin false
        JoinUI->>JoinUI: redirect to login
    else new user
        Server->>DB: create User with pin null
        Server->>DB: create ProjectMember
        Server-->>JoinUI: needsPin true
        JoinUI->>JoinUI: show create-PIN step
        Crew->>JoinUI: types new PIN twice
        JoinUI->>Server: createPersonalPin(pin)
        Server->>DB: bcrypt hash - User.pin set
        Server-->>JoinUI: ok
        JoinUI->>JoinUI: redirect to login
    end

    Crew->>Crew: signs in at login

2. Change request: submit, review, resolve

sequenceDiagram
    actor Crew
    participant PS as Panel Studio (client)
    participant Server as Server Actions
    participant DB
    actor Admin
    participant Tasks as Admin Tasks

    Crew->>PS: taps key, picks Cameras
    PS->>PS: key.status = changed (yellow)
    Crew->>PS: clicks Submit
    PS->>Server: submitChanges(items)
    Server->>DB: create ChangeRequest + Items + KeyDraft submitted
    Server-->>PS: ok
    PS->>PS: key.status = submitted (green)
    PS->>PS: start 5s polling

    Tasks->>Server: GET task-count every 5s
    Server->>DB: count CRs + lockouts scoped to admin projects
    Server-->>Tasks: count
    Tasks->>Tasks: badge appears

    Admin->>Tasks: clicks Review
    Tasks->>PS: navigate Panel Studio review mode

    Admin->>PS: toggles keys approve or deny
    Admin->>PS: clicks Resolve
    PS->>Server: resolveChangeRequests
    Server->>DB: update PanelKey for approved - delete KeyDrafts
    Server->>DB: set CR status applied or rejected
    Server-->>PS: ok

    Crew->>PS: poll fires
    PS->>Server: refresh page query
    Server->>DB: fetch PanelKey + recentResolutions (60s window)
    Server-->>PS: new data

    PS->>PS: fingerprint changed
    PS->>PS: initializeKeys from DB

    alt approved
        PS->>PS: toast Your panel changes are live
    else denied
        PS->>PS: toast Keys X Y denied
    end

3. Equipment bulk add (with optional custom ID)

sequenceDiagram
    actor Admin
    participant UI as Equipment Tab
    participant Server as bulkCreateEquipment
    participant DB

    Admin->>UI: clicks Add Equipment
    Admin->>UI: Category Panels, Hardware KP-5032, Qty 5
    alt ID blank
        Note right of Admin: uses category prefix PNL
    else ID P001
        Note right of Admin: prefix P, start 1, padWidth 3
    end
    Admin->>UI: Add

    UI->>Server: bulkCreateEquipment args

    alt blank starting id
        Server->>DB: find highest PNL N in project
        Server->>Server: prefix PNL, start max+1, pad 1
    else P001
        Server->>Server: parse prefix P, start 1, pad 3
    end

    Server->>DB: fetch all equipment names for collision check

    loop until qty reached or safety cap
        Server->>Server: candidate = prefix + separator + number
        alt candidate exists
            Note right of Server: skip, n++
        else free
            Server->>Server: push record, n++
        end
    end

    alt enough
        Server->>DB: createMany
        Server-->>UI: success count
        UI->>UI: toast Added N Panels
    else cap hit
        Server-->>UI: error too many collisions
    end

4. Tasks badge polling

sequenceDiagram
    participant Shell as AppShell
    participant SS as sessionStorage
    participant API as /api/admin/task-count
    participant DB

    Note over Shell: on mount
    Shell->>SS: read task-count-cache
    SS-->>Shell: value
    Shell->>Shell: setTaskCount(cached)
    Shell->>Shell: badge shows instantly

    loop every 5s (admin only)
        Shell->>API: GET task-count
        API->>DB: count grouped CRs + lockouts scoped to admin projects
        API-->>Shell: count
        Shell->>Shell: setTaskCount
        Shell->>SS: write cache
    end

5. Device reachability probing

sequenceDiagram
    participant Hook as useDeviceReachability
    participant SS as sessionStorage
    participant BC as BroadcastChannel
    participant Device as Panel on LAN
    participant Hook2 as Hook in other tab

    Note over Hook: on mount
    Hook->>SS: read cache (TTL 10s)
    alt fresh
        Hook->>Hook: hydrate from cache
    end

    Hook->>BC: subscribe to device-reachability

    Hook->>Hook: checkAll
    loop per device
        Hook->>Device: fetch HTTPS HTTP no-cors
        alt response 25ms+
            Device-->>Hook: any response
            Hook->>Hook: mark reachable
        else under 25ms
            Note right of Hook: likely network reject - discard
        else timeout
            Hook->>Hook: mark unreachable
        end
    end

    Hook->>SS: write cache
    Hook->>BC: postMessage results

    BC-->>Hook2: other tab gets broadcast
    Hook2->>Hook2: adopt results - skip own probe
