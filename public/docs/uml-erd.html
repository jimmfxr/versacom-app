2a. Rack designer subset (v2.4)

Four-entity slice used by the Racks tab + RackStudio + RackPreview. RackTemplate is the rack (one per row on the Racks tab). RackSlot is one rack-unit slot at a given position on one face; equipmentId optionally links it to a real Equipment row so deploy status + location + IP flow through. RackLooseItem is a non-RU device tagged to the rack (chips above the chassis). RackDevice is a project-authored custom device that joins the library (built-in presets live in code).

2b. Switch Studio subset (v2.5)

VlanProfile is global (no projectId) — one company-wide pool seeded from the operator's hex chart. SwitchPort is per-Equipment, lazy-seeded on first Switch Studio open from SwitchModel.defaultFor().

3. Unique constraints

ModelUnique constraintEnforces
ProjectpinNo two active projects share the same 4-digit join PIN
ProjectMember(userId, projectId)A user isn't on the same project twice
PanelKey(projectMemberId, keyIndex, page, expansion)One physical key position per member
AssetqrCodeEvery physical asset has a unique QR
ProjectHeadsetInventory(projectId, headsetType)One brought-total row per headset type per project
RackSlot(rackTemplateId, side, ruPosition) (logical, enforced in code)One slot per RU starting-position per side. Collision detection in the drag pipeline checks every RU the slot would span, not just ruPosition.
VlanProfilevlanIdNo two profiles share a VLAN ID (1331, 1341, 4000…). Names can repeat but the numeric ID is unique.
SwitchPort(equipmentId, portIndex)One row per physical port per switch — lazy-seeded on first Switch Studio open
