Rack Studio — design + edit a rack (v2.4)

The Racks tab under Comms lists every RackTemplate as a single row. Tapping Edit expands the row in place into the full RackStudio (chassis + device library + slot editor + loose-gear tray). All other rows collapse — single-rack focus. The URL stays in sync via ?tab=racks&expand=<rackId> so refreshing or sharing a link lands on the same expansion.

flowchart TD
    RACKS_TAB[Racks tab in Comms] -->|tap Edit on a row| EXPAND[Inline RackStudio
?expand=rackId mirrored to URL]

    EXPAND --> CHASSIS[Chassis - totalRU rows
front or rear side toggle
loose-gear chips above]
    EXPAND --> LIBRARY[Device library
filter dropdown
10 categories]

    LIBRARY --> EQ_TILES[Equipment tiles at top of
Switches and Audio categories

    LIBRARY --> PRESET_TILES[Preset tiles from rack-presets.ts

    EXPAND --> PLACE{Place a slot}
    PLACE -->|drag tile onto RU| DROP[6px threshold then active drag
collision check on every RU spanned]
    PLACE -->|tap empty RU then tap tile| ARM_RU[Arm RU then place by tile tap]
    PLACE -->|tap tile then tap RU| ARM_TILE[Arm tile then place by RU tap]

    DROP --> SLOT_CREATED[RackSlot row created
linked to Equipment if from equipment tile]
    ARM_RU --> SLOT_CREATED

    EDIT_FORM -->|unlinked slot| FIELDS[Device type + Label + RU size]

    EXPAND -->|eye icon| PREVIEW[/projects/ID/racks/RID/preview/]
    EXPAND -->|Close on expanded header| RACKS_TAB
    PREVIEW -->|Close button| RACKS_TAB

Three placement modes (all routed through the same createRackSlot server action — operator picks whichever feels right):

  1. Drag from library → drop on RU. PointerEvents-based; 6px movement threshold so a tap is still a tap. During drag the bottom sheet (mobile) closes so the chassis is fully visible; reopens after drop.
  2. Tap empty RU → arm-then-pick a tile. Tap RU first; library tiles light cyan as droppable; tap a tile to place at the armed RU.
  3. Tap library tile → arm-then-place on RU. Reverse of (2). Tap tile first; chassis empty rows highlight; tap one to place.

Equipment-backed slots (PD-026): only switches + audio category equipment surface as library tiles. Panels are excluded — they sit on desks, not in racks. Once an equipment row is linked to a slot in any rack on this project, its tile disappears from the library to prevent double-placement. The slot card pulls deploy status, location, model, and IP from the linked Equipment row at server-render time.

Loose-gear tray (PD-029): devices with ruSize === 0 (Antaira, Intellanet, TP Link, Bolero Antenna Master, …) render as chips above the chassis. Adding is tap-to-add (no drag). The × removes instantly — no confirmation modal. Re-adding is one tap.

Rack Preview (operator-facing): the eye icon next to Edit opens /projects/[id]/racks/[rackId]/preview — read-only, no navbar, no bottom-nav. Renders both Front + Rear chassis side-by-side on desktop, or as a horizontal scroll-snap carousel with cyan dot indicators on mobile. Slots in the preview show label (white) · linkedLocation (cyan) · linkedHardwareType (gray) for equipment-backed slots; empty rows show RU number + "Empty". Labeled Close button (matches Switch Studio + Panel Studio chrome — PD-033) returns to ?tab=racks&expand=<rackId>.

URL → state restore is one-shot-on-mount (guarded by restoredFromUrlRef); the changeExpandedRack() helper mirrors state to the URL on every toggle. Together these prevent the "press Close → expansion re-opens 1-2 seconds later" bug a background data refresh would otherwise cause with a stale ?expand= still in the URL (PD-028).

Switch Studio — assign VLAN profiles to switch ports (v2.5)

Entry point lives on the Comms Equipment tab: the switch ID text (SW 1, SW 2, …) on each NETGEAR M4250 card is a Link to /projects/[id]/switch/[equipmentId]. Only switches whose hardwareType resolves to a registered model (9P+1F, 26P+4F, 40P+4F, 24X8F8V, 16F) get a clickable ID — unmanaged switches don't have a VLAN config UI.

Chassis grid layout:

  • 1 row: 9P+1F (10 ports linear) · 16F (16 SFP linear)
  • 2 rows: 26P+4F (15×2) · 40P+4F (22×2) · 24X8F8V (20×2)
  • Port number small at the top of each cell; VLAN ID dominant, centered/lower
  • Trunk ports render gray (Management color) + white "T" badge bottom-right, matching NETGEAR ProAV Engage

Mobile UX:

  • Chassis wider than viewport scrolls horizontally; bezel uses mx-auto w-fit so it centers when it fits and anchors to the LEFT edge when it doesn't (scroll reaches both ends — PD-031)
  • Page header (Comms + ProjectSwitcher + bottom border) wraps in AutoHideHeader — slides up on scroll-down, same as the rest of the app
  • Identity strip wraps into 2 rows on small screens (SW 1 · model + Close on row 1, IP · port count on row 2)
  • IP renders as a cyan link → http://<ip> opens NETGEAR's web management UI in a new tab

Server action gate: updateSwitchPort re-checks role before any write. Manager hitting the endpoint directly returns { error: 'Read-only role' }; user is already blocked at the proxy.
